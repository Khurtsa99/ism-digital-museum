# 5–7 минутын demo скрипт

**0:00–0:30 Танилцуулга.** "ISM Digital Museum нь тэнхимийн түүх, багш нар, арга хэмжээ, оюутны бүтээлийг нэг дор харуулдаг, Supabase-тэй холбогдсон веб аппликейшн. React + Supabase + Vercel ашигласан."

**0:30–1:30 Нүүр ба үзмэр.** Нүүр хуудас → Үзмэр. Нэрээр хайх, ангилал, он, технологиор шүүх. Байхгүй зүйл хайж "олдсонгүй" мэдэгдлийг үзүүл. Нэг үзмэр нээж дэлгэрэнгүй, зохиогчийн холбоосоор Creators руу орно.

**1:30–2:30 Багш нар, арга хэмжээ.** Багш нарын хуудас, хайлт. Арга хэмжээний цомог нээж зургийг томруулна.

**2:30–4:00 Бүтээлч шийдэл: Time Machine.** "Түүх, арга хэмжээ, бүтээл, технологийг нэг цаг хугацааны шугамд нэгтгэсэн." Төрлөөр шүүх, нэг үйл явдлыг дэлгэж, дэлгэрэнгүй хуудас руу шилжих. Яагаад энэ санааг сонгосноо хэл: тэнхимийн хөгжлийг нэг дор харуулдаг учраас музейн зорилготой шууд уялдана.

**4:00–5:30 Бүртгэл ба CRUD.** Бүртгүүлэх → нэвтрэх → Миний бүтээл. Бүтээл нэмж зураг upload хийх, засах, устгах. Validation алдааг үзүүл (хоосон гарчиг, буруу холбоос).

**5:30–6:30 RLS ба аюулгүй байдал.** Хоёр дахь хэрэглэгчээр нэвтэрч эхний хэрэглэгчийн бүтээлийг засч чадахгүй байгааг үзүүл. Supabase-ийн Policies хуудсыг нээж `creator_id = auth.uid()` дүрмийг тайлбарла. "Service role түлхүүр frontend-д байхгүй, зөвхөн anon түлхүүр" гэж хэл. Админ хэсгийг товч үзүүл.

**6:30–7:00 Дүгнэлт.** GitHub commit түүх, README, Vercel холбоос, responsive (гар утасны харагдац).

## Хамгаалалтад асуух магадлалтай асуултууд
- RLS гэж юу вэ, яагаад хэрэгтэй вэ? (Мөр түвшний хамгаалалт. Frontend-ийг тойрч API руу шууд хандсан ч өгөгдлийн сан өөрөө эрхийг шалгана.)
- anon түлхүүр ил байж яагаад аюулгүй вэ? (RLS-ээр хязгаарлагдсан тул. service_role л нууц.)
- `useState`, `useEffect` юу хийж байна? (`Exhibits.jsx`: шүүлтүүрийн утга state-д, өөрчлөгдөх бүрт `useEffect` Supabase руу дахин query илгээнэ.)
- Context юу хийдэг вэ? (`AuthContext`: нэвтэрсэн хэрэглэгч, профайлыг бүх компонентод дамжуулна.)
